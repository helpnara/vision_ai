# 비전 기반 표면 결함 탐지 파이프라인

일상 생활에서 접하는 물건의 **표면 결함**을 탐지하는 모델을, **오픈 데이터셋 기반**으로
개발하기 위한 Streamlit 앱이다. 수집 → 라벨링 → 모델 개발/평가 → 운영관리(MLOps)를
한 앱에서 순차적으로 다룬다.

> **데이터 원칙**: 사내(회사) 결함 데이터는 사용하지 않는다. 공개 데이터셋과 직접 촬영한
> 이미지만 사용한다.

## 진행 상태

| 단계 | 기능 | 상태 |
|------|------|------|
| 1 | 데이터 수집 (입력) | ✅ 구현 완료 |
| 2 | 라벨링 | ✅ 구현 완료 |
| 3 | 모델 개발 · 평가 | ⬜ 예정 |
| 4 | 사후 운영관리 (MLOps) | ⬜ 예정 |

**기본 예시 데이터셋: [VisA](https://github.com/amazon-science/spot-diff)** (CC BY 4.0).
상업적 이용이 가능해 이후 회사 업무로 연장할 때 데이터셋을 갈아치우지 않아도 된다.
(MVTec AD는 일상 품목이 많지만 CC BY-NC-SA로 비상업 한정이라 기본값에서 제외했다.)

설계 배경과 결정 이력은 [`docs/surface-defect-detection-plan.md`](docs/surface-defect-detection-plan.md)에 있다.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

`app.py`가 진입점이다. `src/`를 import 경로에 자동으로 추가하므로 별도 설치 없이 실행된다.
패키지로 설치해서 쓰려면 `pip install -e .`도 가능하다.

## 1단계에서 할 수 있는 일

- **오픈 데이터셋 카탈로그** — 표면 결함 데이터셋 7종을 *일상 물건 적합도* 순으로 비교.
  라이선스와 상업적 이용 가능 여부를 함께 표시한다.
- **로컬 폴더 임포트** — 내려받은 데이터셋 폴더를 지정하면 폴더 구조에서 카테고리·분할·
  정상/결함·결함 유형을 자동 추론한다. 등록 전에 추론 결과를 미리 확인할 수 있다.
  원본 파일은 이동·복사하지 않고 경로만 인덱싱한다.
- **이미지 업로드** — 직접 촬영한 일상 물건 사진을 올려 검증셋으로 사용.
- **합성 샘플 생성** — 외부 다운로드 없이 VisA(또는 MVTec) 구조의 가짜 표면 이미지를
  **결함 마스크와 함께** 만들어 전체 파이프라인을 먼저 돌려볼 수 있다.
  *(성능 근거로는 쓸 수 없다.)*
- **수집 현황** — 카테고리/결함 유형 분포, 클래스 불균형 경고, 품질 점검(흐림·노출·해상도),
  이미지 미리보기, manifest 내려받기.

## 2단계에서 할 수 있는 일

- **라벨 검수 큐** — 한 장씩 띄워 정상/결함과 결함 유형을 지정한다. 결함으로 판정하면
  유형을 고르기 전까지 저장이 막힌다(그냥 눌러서 오라벨이 붙는 것을 방지).
- **마스크 기반 ROI 자동 추출** — VisA·MVTec이 제공하는 결함 픽셀 마스크에서 바운딩박스를
  계산해 제안한다. 마스크가 없으면 슬라이더로 직접 지정한다. 저장 전에 이미지 위에 미리 표시된다.
- **폴더 라벨 검증** — 폴더 구조에서 추론한 라벨을 표본으로 눈으로 확인하고 오라벨을 고친다.
- **결함 유형 정규화** — 데이터셋 고유 유형명(예: `broken_large`)을 프로젝트 표준 10종으로 매핑한다.
  모르는 유형을 임의로 `other`로 뭉개지 않고 매핑이 필요하다는 사실을 드러낸다.
- **층화 분할** — 카테고리 × 라벨 비율을 유지한 train/val/test 분할. VisA의 공식
  `split_csv/`를 임포트해 벤치마크와 비교 가능한 분할을 쓸 수도 있다.
- **라벨 현황** — 진행 지표, 분포, 라벨 이력, 유효 라벨 내려받기.

### 데이터 시작하기

오픈 데이터셋을 아직 내려받지 않았다면 **합성 샘플 생성** 탭으로 시작하는 것이 가장 빠르다.
기본값이 VisA 구조라서 마스크 기반 ROI 추출까지 그대로 시험할 수 있다.

실제 VisA로 진행할 때는 압축 해제한 루트 폴더를 **로컬 폴더 임포트**에 지정하면 된다
(구조 해석 방식 `visa`). 형식 변환은 필요 없다. VisA는 결함 유형을 폴더로 나누지 않으므로
모든 결함이 `유형 미지정`으로 들어오고, 2단계 라벨 검수에서 유형을 지정하는 흐름이 된다.

## 구조

```
app.py                     Streamlit 진입점 (네비게이션)
app_pages/                 단계별 화면
  home.py                  진행 현황 대시보드
  p1_ingest.py             1단계: 데이터 수집
  p2_labeling.py           2단계: 라벨링
  p3_modeling.py           3단계: 모델 개발·평가 (예정)
  p4_operations.py         4단계: 운영관리 (예정)
src/vision_ai/             코어 로직 (UI와 분리 — 테스트 가능)
  config.py                경로, 라벨/결함 유형 체계
  storage.py               manifest 읽기/쓰기, 중복 제거
  datasets.py              오픈 데이터셋 카탈로그, 폴더 구조 파서
  quality.py               이미지 품질 점검
  ingest.py                수집 로직 + 합성 데이터 생성
  labeling.py              라벨 이력·유형 매핑·분할·마스크 ROI
  viz.py                   ROI/마스크 오버레이, 크롭
tests/                     pytest
data/                      수집 이미지, manifest (git 추적 제외)
artifacts/                 모델, 리포트 (git 추적 제외)
```

### 데이터 계층

manifest는 **수집한 사실**만 담고, 사람의 판정은 별도 계층으로 분리한다. 유효 라벨은
`labeling.resolve()`가 세 계층을 겹쳐 계산한다.

| 파일 | 성격 | 내용 |
|------|------|------|
| `data/manifest.csv` | 수집 사실 (1단계) | 출처·카테고리·폴더 추론 라벨·품질 지표. sha1로 중복 제거 |
| `data/labels.csv` | 사람 판정 이력 (append-only) | 누가 언제 무엇을 어떻게 바꿨는지. 최신 이벤트가 유효 라벨 |
| `data/splits.csv` | 파생 데이터 | image_id → train/val/test. 언제든 재생성 가능 |
| `data/defect_type_map.csv` | 정규화 규칙 | 데이터셋 고유 유형명 → 표준 유형 |

manifest를 직접 고치지 않기 때문에, 라벨을 되돌리거나 판정 근거를 되짚어 볼 수 있다.
