# 비전 기반 표면 결함 탐지 파이프라인

물건 표면의 **결함**을 탐지하는 모델을 **오픈 데이터셋 기반**으로 개발하기 위한 Streamlit 앱이다.
수집 → 라벨링 → 모델 개발/평가 → 운영관리(MLOps)를 한 앱에서 순차적으로 다룬다.
**제조업 기준 PoC**로, VisA의 PCB 4종(pcb1~4)을 1차 대상으로 한다.

> **데이터 원칙**: 사내(회사) 결함 데이터는 사용하지 않는다. 공개 데이터셋과 직접 촬영한
> 이미지만 사용한다.

## 진행 상태

| 단계 | 기능 | 상태 |
|------|------|------|
| 1 | 데이터 수집 (입력) | ✅ 구현 완료 |
| 2 | 라벨링 | ✅ 구현 완료 |
| 3 | 모델 개발 · 평가 | ✅ 구현 완료 |
| 4 | 사후 운영관리 (MLOps) | ✅ 구현 완료 |

**기본 예시 데이터셋: [VisA](https://github.com/amazon-science/spot-diff)** (CC BY 4.0).
상업적 이용이 가능해 이후 회사 업무로 연장할 때 데이터셋을 갈아치우지 않아도 된다.
(MVTec AD는 일상 품목이 많지만 CC BY-NC-SA로 비상업 한정이라 기본값에서 제외했다.)

설계 배경과 결정 이력은 [`docs/surface-defect-detection-plan.md`](docs/surface-defect-detection-plan.md)에,
다음에 할 일은 [`docs/todo.md`](docs/todo.md)에 있다.
영상에서 프레임을 뽑아 라벨링하는 기능은 [`docs/video-frame-extraction-plan.md`](docs/video-frame-extraction-plan.md)에
설계와 진행 상황이 있다 (추출·그룹 분할·구간 라벨링·다중 박스까지 구현, 실제 촬영본 측정이 남았다).

## 실측 성능 (VisA PCB 4종)

합성 데이터가 아닌 **실제 VisA 데이터**로 공식 1cls 분할에서 측정한 값이다.
전체 결과: [`docs/results/visa_validation.md`](docs/results/visa_validation.md)

| 카테고리 | AUROC | AP | 재현율 | 정밀도 | 오탐률 |
|---|---|---|---|---|---|
| pcb1 | 0.829 | 0.789 | 0.940 | 0.681 | 0.440 |
| pcb2 | 0.864 | 0.818 | 0.960 | 0.676 | 0.460 |
| pcb3 | 0.682 | 0.703 | 0.960 | 0.565 | 0.725 |
| pcb4 | 0.947 | 0.931 | 0.840 | 0.808 | 0.196 |
| **평균** | **0.830** | **0.811** | **0.925** | 0.683 | 0.455 |

임계값은 test의 절반에서 고르고 나머지 절반에서만 지표를 냈다 — 같은 데이터로 고르고
보고하면 수치가 부풀려지기 때문이다. AUROC/AP는 임계값과 무관해 test 전체 기준이다.

**정밀도를 현장 기대치로 읽으면 안 된다.** 시험 구성이 정상:결함 = 1:1이다.
불량률 1%로 환산하면 기대 정밀도는 **2.0%** 로 떨어진다. 즉 이 모델은 자동 판정용이 아니라
**1차 스크리닝용**이다.

업무 언어로 옮기면 이렇다 (불량률 1%, 1,000장 기준).

| | 값 |
|---|---|
| 검수량 절감 | **54%** — 사람이 볼 물량이 1,000장 → 460장 |
| 놓치는 결함 | **1건** (결함 10건 중) |
| 걸러내야 할 오탐 | 451건 |

절감만 보면 안 된다. 줄이는 대가가 놓치는 결함이므로 앱에서도 두 값을 항상 나란히 보여준다
(`evaluate.business_impact`). 3단계 평가 화면에서 불량률과 물량을 직접 바꿔볼 수 있다.

재현:
```bash
PYTHONPATH=src python scripts/validate_visa.py       # 측정
PYTHONPATH=src python scripts/analyze_visa_results.py # 해석 (불량률별 환산)
```

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

홈 화면이 **지금 어디까지 왔고 다음에 무엇을 할지** 알려주므로, 순서를 몰라도 따라갈 수 있다.
지표는 핵심만 캡션으로 바로 보이고 나머지는 `?`에 있으며, 평가 결과에는 **다음에 할 일**이 함께 나온다.
처음이라면 홈의 **⚡ 데모 한 바퀴 만들기**를 누르면 합성 데이터 생성부터 모델 승격까지 한 번에 끝난다.

`app.py`가 진입점이다. `src/`를 import 경로에 자동으로 추가하므로 별도 설치 없이 실행된다.
패키지로 설치해서 쓰려면 `pip install -e .`도 가능하다.

## 1단계에서 할 수 있는 일

- **오픈 데이터셋 카탈로그** — 표면 결함 데이터셋 7종을 *일상 물건 적합도* 순으로 비교.
  라이선스와 상업적 이용 가능 여부를 함께 표시한다.
- **로컬 폴더 임포트** — 내려받은 데이터셋 폴더를 지정하면 폴더 구조에서 카테고리·분할·
  정상/결함·결함 유형을 자동 추론한다. 등록 전에 추론 결과를 미리 확인할 수 있다.
  원본 파일은 이동·복사하지 않고 경로만 인덱싱한다.
- **이미지 업로드** — 직접 촬영한 사진을 올려 보조 검증셋으로 사용.
- **영상에서 프레임 추출** — 현장에서 데이터를 모으는 방식은 대체로 영상 촬영이다.
  뽑는 간격을 감으로 정하지 않고 **초당 장수**나 **공정 값(시야 길이·라인 속도·물체당 장수)**
  으로 계산한다. 같은 식을 뒤집어 **최소 요구 fps**를 내므로, 라인이 빨라 지금 카메라로는
  안 되는 경우를 프레임을 뽑기 전에 알 수 있다. 정지 구간에서 쏟아지는 거의 같은 프레임은
  걸러낸다. 뽑은 프레임에는 **영상 id를 그룹으로 달아** 2단계 분할이 학습/평가에 섞지 않게 한다.
  영상은 **목록에서 고른다** — 경로를 통째로 타이핑하면 오타로 실패할 뿐 아니라 어떤 영상이
  이미 올라와 있는지 화면에서 알 수가 없다. 프로젝트 영상 폴더를 훑고, 영상이 프로젝트 밖에
  있으면 폴더를 적어 함께 훑는다. 영상이 없으면 시험용 영상을 만들어 바로 시험할 수 있다.
- **합성 샘플 생성** — 외부 다운로드 없이 VisA(또는 MVTec) 구조의 가짜 표면 이미지를
  **결함 마스크와 함께** 만들어 전체 파이프라인을 먼저 돌려볼 수 있다.
  *(성능 근거로는 쓸 수 없다.)*
- **수집 현황** — 카테고리/결함 유형 분포, 클래스 불균형 경고, 품질 점검(흐림·노출·해상도),
  이미지 미리보기, manifest 내려받기.

## 2단계에서 할 수 있는 일

- **라벨 검수 큐** — 한 장씩 띄워 정상/결함과 결함 유형을 지정한다. 결함으로 판정하면
  유형을 고르기 전까지 저장이 막힌다(그냥 눌러서 오라벨이 붙는 것을 방지).
- **영상 구간 라벨링** — 검사원은 프레임을 한 장씩 보지 않는다. 영상을 돌려 보며 "여기부터
  여기까지 불량"이라고 짚는다. **타임라인에서 구간을 끌면 그 구간의 프레임에 라벨이 한 번에**
  붙는다. 3,000장을 한 장씩 보게 만들면 영상을 쓰는 이유가 사라진다.
- **마스크 기반 ROI 자동 추출과 다중 박스** — VisA·MVTec이 제공하는 결함 픽셀 마스크에서
  바운딩박스를 계산해 제안한다. 마스크가 없으면 **이미지 위에서 드래그해 직접 지정**한다 —
  지정한 영역 안쪽을 끌면 위치를 옮길 수 있다. 한 장에 결함이 여럿이면 **박스를 여러 개**
  그릴 수 있고, 번호가 이미지와 목록에 함께 붙어 어느 것이 어느 유형인지 보인다. 유형을
  나중에 골라도 이미 그린 박스에 반영된다.
- **작은 결함을 위한 확대** — VisA PCB 결함은 이미지의 0.57%다. 1404px 이미지를 640px로
  줄여 그리면 화면 1px이 원본 2.2px이라, 결함이 보이지도 정확히 그려지지도 않는다.
  **조작은 늘리지 않았다** — 대충 끌고 「지정한 영역으로 확대」를 누르면 그 둘레로 확대되고
  그 안에서 다시 그린다. 같은 크기로 끌어도 잡히는 범위가 112×107에서 25×24로 줄어든다.
  지금 화면에서 그릴 수 있는 가장 작은 눈금을 항상 표시한다.
  (별도 캔버스 컴포넌트를 쓰지 않고 Streamlit에 들어 있는 Vega-Lite 구간 선택으로 구현했다.)
- **폴더 라벨 검증** — 폴더 구조에서 추론한 라벨을 표본으로 눈으로 확인하고 오라벨을 고친다.
- **결함 유형 정규화** — 데이터셋 고유 유형명(예: `broken_large`)을 프로젝트 표준 10종으로 매핑한다.
  모르는 유형을 임의로 `other`로 뭉개지 않고 매핑이 필요하다는 사실을 드러낸다.
- **층화 분할** — 카테고리 × 라벨 비율을 유지한 train/val/test 분할. **무엇을 하나로 묶어
  옮길지**(영상 단위 / 시간 순서 / 무작위)를 고를 수 있다. 같은 영상의 프레임은 서로 너무
  비슷해서 무작위로 나누면 성능이 실제보다 높게 나오므로, 영상 프레임이 있는데 무작위를
  고르면 경고한다. VisA의 공식 `split_csv/`를 임포트해 벤치마크와 비교할 수도 있다.
- **라벨 현황과 박스 내보내기** — 진행 지표, 분포, 라벨 이력, 유효 라벨 내려받기.
  박스는 고치기 쉬운 CSV로 두고 **내보낼 때** 변환한다 — COCO JSON, 또는 이미지당 txt 한 개와
  `classes.txt`가 든 YOLO zip. 변환은 언제든 다시 할 수 있지만 편집 이력은 한 번 잃으면 끝이다.
- **지도학습 검출 준비** — 지금 모델(이상탐지)은 "정상과 얼마나 다른가"를 잰다. "스크래치 2개와
  찍힘 1개"처럼 무엇이 몇 개인지 알려면 박스로 학습하는 검출 모델이 필요하다. 학습 폴더
  (`images/` + `labels/` + `data.yaml`)를 만들어 주고, 학습은 GPU가 있는 기계에서
  `scripts/train_detector.py`로 돌린다. **결함이 한 장도 없는 폴더는 막는다** — 그대로
  학습하면 모델은 "결함은 없다"만 배우고, 아무것도 못 찾으면서 지표는 훌륭하게 나온다.

## 3단계에서 할 수 있는 일

딥러닝 스택 없이 **scikit-learn + OpenCV**로 구성했다. 설치 부담이 작고, 표면 결함이 국소적인
밝기·엣지·텍스처 이상으로 나타난다는 성질을 직접 활용한다.

- **베이스라인** — 이미지 1장을 67차원 특징(밝기 분위수·Laplacian·Sobel·Canny·색상·고주파·LBP 등)으로
  요약해 분류기 3종 중 하나로 학습한다. 이후 모델이 이보다 나은지 판단하는 하한선.
- **패치 이상탐지** — **정상 이미지만** 학습해 격자 위치별 정상 분포를 만들고, 마할라노비스 거리를
  결함 점수로 쓴다. 거리 지도가 곧 **결함 위치 히트맵**이라 별도 위치 예측기가 없다.
  특징은 고전 CV가 기본이고, 사전학습 CNN(ResNet18 ONNX)도 고를 수 있다 —
  다만 **측정해 보니 이미지 판정은 소폭 나아지고 위치 찾기는 크게 나빠져서** 선택 기능이다
  (설계 문서 4.6).
- **Claude 2차 판정** — 1차 모델 점수가 임계값 **근처**인 애매한 이미지만 `claude-opus-5`에 ROI 크롭으로
  보내, 결함 유형·심각도·확신도와 **근거 문장**을 JSON 스키마로 받는다. 결과는 캐시해 재청구를 막는다.
- **평가 리포트** — 임계값 슬라이더로 미탐/오탐 트레이드오프를 직접 보고, 혼동행렬·ROC와 함께
  **오탐·미탐 샘플 갤러리**를 띄운다. 숫자만으로는 다음 조치가 정해지지 않는다.
- **실험 기록** — 학습할 때마다 설정과 지표가 한 줄씩 쌓여 실행 간 비교가 된다.
- **결과 보고서** — 성능·업무 효과·판정·주의사항을 마크다운 한 장으로 내려받는다.

**임계값 결정 방식**: 목표 재현율(기본 0.95)을 먼저 정하고, 이를 만족하는 임계값 중 **오탐이 가장 적은
값**을 자동 선택한다. 미탐(결함을 놓침)을 최우선 리스크로 보는 정책을 코드로 표현한 것이다.

**목표 재현율은 고정값이 아니다.** 미탐 1건의 비용이 큰 라인이면 **설정** 화면에서 올리면 되고,
바꾸면 3단계 임계값 선택과 4단계 승격 점검이 함께 그 값을 쓴다. 불량률·검사 물량·재학습 기준도
같은 화면에서 조정한다.

### Claude 2차 판정 사용 조건

```bash
pip install anthropic          # requirements.txt에 포함되어 있다
export ANTHROPIC_API_KEY=...   # 또는 `ant auth login` 프로필
```

키가 없어도 나머지 기능은 모두 동작한다. 호출 전 화면에 예상 비용이 표시된다.

### 데이터 시작하기

오픈 데이터셋을 아직 내려받지 않았다면 **합성 샘플 생성** 탭으로 시작하는 것이 가장 빠르다.
기본값이 VisA 구조라서 마스크 기반 ROI 추출까지 그대로 시험할 수 있다.

실제 VisA로 진행할 때는 압축 해제한 루트 폴더를 **로컬 폴더 임포트**에 지정하면 된다
(구조 해석 방식 `visa`). 형식 변환은 필요 없다. VisA는 결함 유형을 폴더로 나누지 않으므로
모든 결함이 `유형 미지정`으로 들어오고, 2단계 라벨 검수에서 유형을 지정하는 흐름이 된다.

## 4단계에서 할 수 있는 일

모델을 만드는 것보다 **만든 뒤 성능이 떨어지는 것을 알아채는 일**이 어렵다. 성능 저하는 두 경로로
오고 조치가 다르므로, 나눠서 감시한다.

| 경로 | 감지 방법 | 정답 라벨 | 조치 |
|------|-----------|-----------|------|
| **데이터 드리프트** | 학습 시 입력 분포 대비 PSI | 불필요 | 재학습·전처리 조정 (조명·공정 변경 확인이 먼저) |
| **성능 드리프트** | 사후 검수 정답 vs 모델 판정 | 필요 | 임계값 재조정 또는 모델 교체 |

- **운영 시나리오 시연** — 운영 감시 기능들은 시간이 쌓여야 의미가 생겨서, 앱을 처음 열면
  화면이 전부 비어 있다. 버튼 한 번으로 **운영 3개월치를 재생**해 나머지 탭을 실제로 채운다.
  다른 탭과 같은 코드를 그대로 돌리되 추론 시각을 과거로 채우고 조명·초점 변화를 입힌다.
  *(시연용 수치이지 성능 근거가 아니다.)*
- **모델 레지스트리** — 3단계 실행을 버전으로 승격한다. 승격 시 모델 파일을 **버전 폴더로 복사**하므로
  이후 학습이 같은 경로를 덮어써도 롤백할 수 있다. 이전 버전은 보관 상태로 남아 다시 승격하면 롤백된다.
- **배치 추론** — 등록된 버전으로 이미지를 판정하고 로그를 남긴다. 로그가 없으면 성능 저하를 감지할
  근거 자체가 없다.
- **드리프트 감시** — 승격 시 저장한 기준선과 최근 입력의 분포를 PSI로 비교한다. 정답 라벨 없이
  동작해 사후 검수보다 먼저 경고를 준다.
- **성능 추이** — 2단계에서 **사람이 확인한** 라벨만 정답으로 써서 실측 재현율을 계산한다.
  폴더 구조에서 추론한 라벨을 정답으로 쓰면 자기 채점이 된다.
- **재학습 판단** — 신호를 모아 제안을 만들되 **자동 배포는 하지 않는다.** 사람이 승인한다.
- **판정 이력 조회** — 이미지 하나의 수집 → 라벨 이력 → 모델 판정 → Claude 근거를 한 화면에 모은다.

**PSI 주의점**: 표본이 적으면 같은 분포에서도 PSI가 커진다(10구간 기준 n=40에서 중앙값 0.24).
그래서 표본 수에 맞춰 구간을 병합하고, 60건 미만이면 판정을 보류한다.

### 데이터 계층

manifest는 **수집한 사실**만 담고, 사람의 판정은 별도 계층으로 분리한다. 유효 라벨은
`labeling.resolve()`가 세 계층을 겹쳐 계산한다.

| 파일 | 성격 | 내용 |
|------|------|------|
| `data/manifest.csv` | 수집 사실 (1단계) | 출처·카테고리·폴더 추론 라벨·품질 지표. sha1로 중복 제거 |
| `data/labels.csv` | 사람 판정 이력 (append-only) | 누가 언제 무엇을 어떻게 바꿨는지. 최신 이벤트가 유효 라벨 |
| `data/splits.csv` | 파생 데이터 | image_id → train/val/test. 언제든 재생성 가능 |
| `data/defect_type_map.csv` | 정규화 규칙 | 데이터셋 고유 유형명 → 표준 유형 |
| `artifacts/experiments.csv` | 실험 기록 (3단계) | 실행별 설정·지표. 상세는 `artifacts/runs/<run_id>.json` |
| `artifacts/claude_reviews.csv` | Claude 판정 캐시 | 같은 이미지를 두 번 청구하지 않기 위한 결과 보관 |
| `artifacts/models/` | 학습된 모델 | 베이스라인(joblib) · 이상탐지(npz) |
| `artifacts/registry.csv` | 모델 레지스트리 (4단계) | 버전·상태(서비스 중/후보/보관)·지표 |
| `artifacts/registry/<version>/` | 버전 스냅샷 | 모델 파일 복사본 + 드리프트 기준선. 3단계가 덮어써도 롤백 가능 |
| `artifacts/inference_log.csv` | 추론 로그 (4단계) | 버전·점수·판정·처리 시간. 드리프트·성능 감시의 근거 |

manifest를 직접 고치지 않기 때문에, 라벨을 되돌리거나 판정 근거를 되짚어 볼 수 있다.

## 배포 (Streamlit Community Cloud)

| 항목 | 값 |
|------|-----|
| Repository | `helpnara/vision_ai` |
| Branch | `claude/vision-surface-defect-detection-j16xhj` |
| Main file path | `app.py` |
| Python version | 3.11 (3.10 이상이면 동작) |
| Secrets | `ANTHROPIC_API_KEY` (선택) |

배포 관련 설정은 저장소에 포함되어 있다.

- `requirements.txt` — 의존성. `opencv-python-headless`를 쓰므로 `packages.txt`(apt 패키지)가 필요 없다.
  일반 `opencv-python`으로 바꾸면 `libGL.so.1` 오류로 기동에 실패한다.
- 데이터와 산출물은 **프로젝트(작업공간)별로 나뉜다.** 현장·라인마다 데이터·라벨·모델·판정
  기준을 따로 관리한다. 한 manifest에 섞으면 정상 분포가 넓어져 결함을 놓치고, 성능 지표도
  여러 현장의 평균이 되어 어디가 문제인지 알 수 없게 된다.

  ```
  data/projects/<slug>/       manifest.csv · labels.csv · splits.csv · settings.json · raw/
  artifacts/projects/<slug>/  models/ · reports/ · cache/ · registry.csv · runs/
  artifacts/shared/models/    사전학습 CNN (프로젝트 공통 — 45MB를 다시 받을 이유가 없다)
  data/projects.json          프로젝트 목록 + 활성 프로젝트
  ```

  활성 프로젝트는 **파일에 둔다.** 세션에 두면 브라우저 탭마다 다른 프로젝트를 보게 되고
  `scripts/`의 측정 스크립트가 어느 것을 봐야 할지 알 수 없다. 사이드바에서 전환하고,
  만들기·이름 바꾸기는 설정 화면에 있다.
- `.streamlit/config.toml` — 테마·업로드 상한. 서버 주소/포트는 고정하지 않는다(클라우드가 지정).
  글자 크기(`baseFontSize`·`headingFontSizes`·`metricValueFontSize`)도 여기서 줄인다. 기본값은
  발표 슬라이드에 가까워서 작업용으로는 한 화면에 들어오는 정보가 너무 적다. CSS를 주입하지
  않고 Streamlit이 공식 지원하는 테마 옵션만 쓰므로 버전이 올라가도 깨지지 않는다.
  `base`는 고정하지 않는다. 비워 두면 보는 사람의 밝게/어둡게 설정을 따라간다.
- 여백·사이드바 레일 폭·탭 줄바꿈은 테마 옵션으로 다룰 수 없어 `src/vision_ai/ui.py`에서 CSS로
  보정한다. 선택자는 `data-testid`와 위젯 key가 만드는 `st-key-*`만 쓴다 — 둘 다 Streamlit이
  밖으로 약속한 표식이고, `st-emotion-cache-*` 클래스는 빌드마다 바뀐다.
  사이드바는 **펼침 / 레일(아이콘만)** 을 오가고, 레일에서도 현재 페이지에 배경 표시가 남아
  "지금 몇 단계인지"를 잃지 않는다. 접기 버튼은 화면 폭에 따라 의미가 달라진다 — 넓은 화면에서는
  레일 토글, 640px 이하에서는 Streamlit 기본 동작(패널 치우기)이며, 보이는 버튼은 항상 하나다.
- `.streamlit/secrets.toml.example` — 시크릿 형식. 실제 `secrets.toml`은 커밋하지 않고
  앱 설정 화면(Settings → Secrets)에 붙여넣는다. Streamlit이 최상위 시크릿을 환경변수로도
  올려주므로 코드는 `os.environ`만 읽으면 된다.
- 페이지 디렉터리를 `pages/`가 아닌 `app_pages/`로 둔 이유는, Streamlit이 `pages/`를 자동
  탐지해 `st.navigation`으로 구성한 메뉴와 중복되기 때문이다.

### 배포 환경에서 달라지는 점

무료 배포 환경은 **컨테이너가 일회성**이다. 재시작하면 `data/`·`artifacts/`가 비워지므로
수집한 이미지, 라벨, 학습한 모델, 레지스트리, 판정 이력이 **모두 사라진다.**
따라서 배포본은 다음 용도로 본다.

- 적합: 화면·흐름 시연, 합성 샘플로 파이프라인 한 바퀴 돌려보기, 설계 리뷰
- 부적합: 실제 라벨링 작업, VisA 전체 학습, 운영 이력 축적

또한 공개 배포 시 접속자 전원이 같은 컨테이너의 CSV를 공유하며, 이 앱에는 로그인·권한 개념이
없다. 여러 명이 동시에 라벨을 쓰면 서로의 작업에 섞인다. 실제 라벨링과 실데이터 학습은
**로컬 실행**을 쓴다.
