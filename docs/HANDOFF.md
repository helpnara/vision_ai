## 4. 검증용 프로젝트(«V3 확인용» · «V4 확인용») — ⚠️ 이 컨테이너에 없다

**먼저 알아야 할 것: 두 프로젝트는 지금 존재하지 않는다.**

```
data/projects/     → default 하나뿐 (raw/ interim/ 모두 비어 있음)
artifacts/projects/→ default 하나뿐
```

위 폴더마저 **이번 세션에 앱을 띄우면서 `projects.bootstrap()`이 방금 만든 빈 껍데기**다.
`data/`·`artifacts/`는 `.gitignore`에 있어 **저장소에 없고**, 원격 컨테이너는 일회성이라
이전 세션이 끝나면서 통째로 사라졌다. 커밋되지 않은 검증 데이터는 되살릴 수 없다.

**따라서 V3·V4 화면을 다시 눈으로 보려면 재현해야 한다.** 무엇이 들어 있었는지는
`docs/todo.md`의 V3·V4 항목에 실측 결과로 남아 있으므로, 아래대로 다시 만들면 된다.

### «V3 확인용»에 있던 것

**목적**: 프레임 지표와 구간 지표가 갈리는 것을 화면이 경고하는지 확인.

* 합성 라인 영상 1개 — **24초 · 72프레임 · 정답 구간 3곳**
* 구간 라벨링으로 붙인 정답 (`label_source=human` · `verified=True` — 폴더 추론 라벨은 자기
  채점이라 성능 측정에서 배제되므로 **반드시 구간 라벨로 붙여야 한다**)
* 이상탐지 모델 1개를 승격해 두고 **임계값만 4.0 → 20.0으로 올려 가며** 4단계 배치 추론 반복

재현하면 이 표가 나와야 한다 (todo.md V3의 실측):

| 임계값 | 프레임 재현율 | 구간 재현율 | 헛알람 |
|---|---|---|---|
| 4.0 | 1.00 | 1.00 | 2건 (분당 5.1회) |
| 12.0 | 0.77 | 1.00 | 0 |
| 16.0 | 0.55 | 1.00 | 0 |
| 20.0 | **0.23** | **1.00** | **0** |

**이 항목의 존재 이유가 임계값 20에 있다.** 프레임 재현율 0.23만 보면 «못 쓴다»지만,
결함 구간 3곳을 다 잡고 헛알람이 0건이라 **현장 기준으로는 가장 좋은 운영점**이다.
두 숫자가 벌어지면 `SegmentReport.contrast()`가 말로 알려 주는지까지 확인한 것이 V3다.

### «V4 확인용»에 있던 것

**목적**: 성능이 떨어졌을 때 «모델 탓인가 촬영 탓인가»를 화면이 가르는지 확인.

* **영상 A**(학습 영상)와 **영상 B**(평가 영상) 2개. 영상 B는 **조명을 밝게 바꾼 촬영본**이다
* 양쪽 모두 구간 라벨 + 4단계 배치 추론 로그(`group` 열에 영상 id가 붙어 있어야 영상별로 갈린다)

**이 프로젝트가 지표의 구멍을 하나 잡아냈다.** 영상 B에서 구간 재현율이 0.67 → **1.00**,
헛알람 0건으로 «좋아졌다»고 나왔는데, 실제로는 모델이 **전 프레임을 결함이라고** 판정한
것이었다. 헛알람을 «정답 구간과 겹치지 않은 예측 구간»으로 세고 있었기 때문이다 —
전 구간에 알람을 켜면 예측 구간이 하나뿐이고 그것이 모든 정답 구간과 겹치므로
**가장 나쁜 모델이 만점을 받는다.**

고친 뒤 같은 데이터가 «정상인데 알람 100%»로 찍히고 결론도 «촬영이 달라진 탓»으로 바로 선다.
이 회귀는 코드로 잠가 두었으므로 **데이터가 없어도 확인할 수 있다**:

```bash
PYTHONPATH=src python -m pytest tests/test_segment_metrics.py -q -k "shouts or flooding or always_on"
```

### 재현 절차 (데이터 없이 시작할 때)

1. 앱을 띄우고 사이드바에서 프로젝트를 새로 만든다 («V3 확인용» 등 한글 이름 그대로 써도 된다 —
   S1에서 폴더명 로마자화를 넣었다)
2. 1단계 → **시험용 영상 만들기**로 합성 영상을 만든다 (`video.py`. 내려받기 없이 생성된다)
3. 1단계 영상 탭에서 프레임 추출 → manifest 등록 (영상 id가 `group` 열에 붙는다)
4. 2단계 **영상 구간 라벨링**에서 정답 구간을 끌어 붙인다 — 이것이 성능 측정의 정답이 된다
5. 3단계에서 이상탐지 모델 학습 → 4단계 레지스트리에서 승격
6. 4단계 **배치 추론**에서 «영상 하나»를 골라 판정 → **성능 추이** 탭에서 구간 지표 확인
7. V4는 영상을 하나 더 만들어 같은 절차를 밟은 뒤 **🆚 영상 비교** 탭에서 둘을 고른다

> 홈의 **⚡ 데모 한 바퀴 만들기**(`quickstart.py`)는 **이미지 기반**이라 3·5·6단계는 대신해
> 주지만 **영상·구간 라벨은 만들어 주지 않는다.** §V 화면을 보려면 2·4단계는 손으로 해야 한다.
