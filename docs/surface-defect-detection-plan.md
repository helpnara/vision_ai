## 1. 프로젝트 개요

### 1.1 배경 및 목표
- **배경**: 사람 육안 검사에 의존하던 표면 결함 검사를 비전 기술로 자동화·표준화하여 검사 일관성과 처리량을 높인다.
- **검사 대상**: **일상 생활에서 접할 수 있는 물건의 표면 결함**을 탐지하는 모델을 만든다.
  기본 데이터셋인 VisA의 12개 품목(양초·껌·캐슈너트·마카로니·캡슐 등 생활 품목 + PCB 4종)을 대상으로 한다.
- **데이터 제약**: 회사(사내) 데이터는 활용에 무리가 있어 사용하지 않으며, 오픈 데이터셋과 직접 촬영 이미지만 사용한다.
- **회사 업무 연장 고려**: 이후 사내 과제로 확장할 가능성이 있어, **상업적 이용이 가능한 라이선스**의
  데이터셋만 기본값으로 채택한다 (VisA: CC BY 4.0). 널리 쓰이는 MVTec AD는 비상업(CC BY-NC-SA) 조건이라 제외했다.
- **목표**: 입력 이미지에 대해 (1) 결함 유무 판정, (2) 결함 유형 분류, (3) 결함 위치(영역) 표시를 자동으로 수행한다.
- **성공 기준(초안)**: 아래 [4.2 평가 지표](#42-평가-지표) 참조. 정량 목표는 D5 확정 후 수치화한다.

### 1.2 범위 (Scope)
- **포함**: 데이터 수집/전처리, 결함 정의, 탐지 파이프라인 설계·구현, 평가, 리포팅.
- **제외(확정)**: 실제 생산라인 하드웨어(카메라/PLC) 통합, 대량 실시간 서빙 인프라. 운영 형태는 Streamlit 앱 기반 오프라인/배치로 한다 (**D3**).

### 1.3 용어 정의
| 용어 | 설명 |
|------|------|
| 결함(Defect) | 정상 표면 대비 허용 기준을 벗어난 이상(스크래치, 찍힘, 이물, 얼룩 등) |
| 오탐(False Positive) | 정상을 결함으로 잘못 판정 |
| 미탐(False Negative) | 결함을 정상으로 놓침 (품질 리스크가 가장 큼) |
| ROI | 검사 관심 영역(Region of Interest) |

## 3. 설계 과정 (Design)

### 3.1 접근 방식 후보 비교

| 접근 | 개요 | 장점 | 단점 | 적합 상황 |
|------|------|------|------|-----------|
| A. 고전 CV | 임계값/에지/모폴로지 기반 규칙 | 빠름, 데이터 少, 해석 쉬움 | 조건 변화에 취약 | 결함 패턴이 단순·일정 |
| B. 지도학습 탐지(YOLO 등) | 라벨 이미지로 결함 검출 학습 | 위치+유형 동시 검출, 정확 | 라벨 데이터 필요 | 결함 종류 명확·데이터 확보 |
| C. 이상탐지(anomaly detection) | 정상만 학습, 이탈을 결함으로 | 결함 라벨 거의 불필요 | 유형 분류는 약함 | 결함 샘플 희소 |
| D. Claude 비전 API 직접 판정 | 이미지를 Claude에 전달해 판정/설명 | 라벨 少, 프롬프트로 빠른 시작, 자연어 설명 | 처리량/비용/미세결함 한계 | 소량·애매 케이스·설명 필요 |
| E. 하이브리드(B/C + D) | 전용 모델 1차 스크리닝 + Claude 2차 판정·설명 | 정확도와 설명력 동시 | 구성 복잡 | 실무 균형 (**잠정 채택**) |

> **잠정 채택(가정)**: **E. 하이브리드** — 데이터 상황에 따라 초기엔 C(이상탐지) 또는 D(Claude 직접)로 시작하고,
> 데이터가 쌓이면 B(지도학습)를 추가한다. D2 확정 시 확정.

### 3.2 파이프라인 (초안)

```
[이미지 입력]
    → [전처리: ROI 크롭 / 정규화 / 조명 보정 / 리사이즈]
    → [1차 탐지: 이상탐지 or 전용 검출 모델]  ──(결함 의심 영역)──┐
    → [2차 판정: Claude 비전 API로 유형 분류 + 근거 설명]        │
    → [후처리: 임계값 적용 / 결함 집계 / 합격·불합격 판정]        │
    → [출력: 판정 결과 + 시각화(박스/마스크) + 리포트]  ◀────────┘
```

### 3.3 Claude 연동 설계 (초안)
- **입력**: 원본 또는 크롭된 결함 후보 이미지 + 구조화된 프롬프트(결함 유형 목록, 판정 기준).
- **출력 형식**: JSON 스키마 강제(예: `{"defect": bool, "type": "scratch|dent|...", "severity": 1-5, "reason": "..."}`).
- **역할**:
  - 소량 데이터 단계에서 1차 판정기.
  - 하이브리드 단계에서 전용 모델의 애매한 결과를 재판정하고 **사람이 읽을 수 있는 근거**를 제공.
- **주의**: 미세·저대비 결함은 한계가 있으므로 임계값·해상도 실험 필요. 실시간 처리를 목표로 하지 않으므로(**D3**) 지연시간보다 호출 비용 관리가 관건이다.

### 3.4 구현 아키텍처 — Streamlit 4단계 앱

전체 파이프라인을 **하나의 Streamlit 앱**에서 단계별 페이지로 구현하고, 순차적으로 완성한다.

| 단계 | 페이지 | 주요 기능 | 상태 |
|------|--------|-----------|------|
| 1 | 데이터 수집 (입력) | 오픈 데이터셋 카탈로그, 로컬 폴더 임포트, 이미지 업로드, 합성 샘플 생성, 품질 점검 | ✅ 완료 |
| 2 | 라벨링 | 라벨 검수 큐, 폴더 라벨 검증, 결함 유형 정규화, 마스크 기반 ROI, 층화 분할 | ✅ 완료 |
| 3 | 모델 개발 · 평가 | 베이스라인 → 이상탐지 → Claude 2차 판정, 지표·오탐/미탐 리포트 | ⬜ 예정 |
| 4 | 사후 운영관리 (MLOps) | 모델 레지스트리, 추론 로그, 데이터/성능 드리프트 감시, 재학습 트리거 | ⬜ 예정 |

**설계 원칙**
- **UI와 코어 로직 분리**: 판정·수집 로직은 `src/vision_ai/`에 두고 Streamlit 페이지는 표시만 담당한다.
  로직을 UI 없이 pytest로 검증할 수 있어야 한다.
- **수집 사실과 사람 판정을 분리**: `manifest.csv`는 "어떤 이미지를 어디서 수집했는지"만 담고,
  사람의 라벨 판정은 별도 이력 파일에 쌓는다 ([3.7](#37-라벨-데이터-계층)). manifest를 직접
  고치지 않으므로 라벨을 되돌리거나 판정 근거를 되짚어 볼 수 있다.
- **원본 파일 불변**: 폴더 임포트는 파일을 이동·복사하지 않고 경로만 인덱싱한다.
- **외부 다운로드 없이도 전 과정 실행 가능**: 오픈 데이터셋은 용량이 크고 약관 동의가 필요하므로,
  VisA와 동일한 구조의 합성 데이터를 **결함 마스크까지 포함해** 생성한다. 덕분에 VisA를 내려받기
  전에도 마스크 기반 ROI 추출까지 그대로 시험할 수 있다. (합성 데이터는 성능 근거로 쓰지 않는다.)

### 3.6 데이터셋 선정 근거 (D7)

| 항목 | VisA (채택) | MVTec AD (제외) |
|------|-------------|-----------------|
| 라이선스 | **CC BY 4.0 — 상업적 이용 가능** | CC BY-NC-SA 4.0 — 비상업 한정 |
| 카테고리 | 12종 (양초·껌·캐슈너트·마카로니·캡슐 등) | 15종 (병·칫솔·목재·가죽·카펫 등) |
| 결함 유형 라벨 | Anomaly 하나로만 구분 (유형 없음) | 결함 유형별 폴더 제공 |
| 결함 마스크 | 제공 | 제공 |
| 규모 | 더 큼, 한 이미지에 여러 개체 | 상대적으로 작음 |

**채택 이유**: 이후 회사 업무로 연장할 가능성이 있어 상업적 이용 가능 여부를 가장 앞에 두었다.
MVTec AD가 결함 유형 라벨까지 준다는 점에서 학습에는 더 편하지만, 비상업 조건이라 확장 시
데이터셋을 갈아치워야 한다.

**대가**: VisA는 결함 유형을 구분하지 않으므로 모든 결함이 `유형 미지정` 상태로 들어온다.
따라서 **결함 유형은 2단계에서 사람이 지정**해야 한다. 이 작업량을 줄이는 것이 2단계 검수 큐의
설계 목표였다.

### 3.7 라벨 데이터 계층

manifest 위에 세 계층을 얹어 유효 라벨을 계산한다 (`labeling.resolve()`).

| 파일 | 성격 | 내용 |
|------|------|------|
| `data/manifest.csv` | 수집 사실 (1단계) | 출처·카테고리·폴더 추론 라벨·품질 지표 |
| `data/labels.csv` | 사람 판정 이력 (append-only) | 누가 언제 무엇을 바꿨는지. **최신 이벤트가 유효 라벨** |
| `data/splits.csv` | 파생 데이터 | image_id → train/val/test. 언제든 재생성 가능 |
| `data/defect_type_map.csv` | 정규화 규칙 | 데이터셋 고유 유형명 → 표준 유형 |

```
유효 라벨 = 폴더 구조 추론 라벨
            → 결함 유형 정규화 매핑 적용
            → 사람 판정 이벤트로 덮어쓰기 (label_source="human")
            → 분할 정보 병합
```

라벨을 덮어쓰지 않고 이벤트로 쌓기 때문에, 나중에 "이 이미지는 왜 결함으로 분류됐나"를
되짚어 볼 수 있다. 4단계 운영관리에서 판정 이력 조회의 토대가 된다.

### 3.8 결함 유형 분류 체계 (확정)

일상 물건 기준으로 정의한다. 오픈 데이터셋의 고유 유형명(예: MVTec AD의 `broken_large`)은
2단계 라벨링에서 아래 표준 유형으로 정규화한다.

| 키 | 설명 | 키 | 설명 |
|----|------|----|------|
| `scratch` | 스크래치 / 긁힘 | `contamination` | 이물 부착 |
| `dent` | 찍힘 / 눌림 | `broken` | 파손 / 깨짐 |
| `crack` | 균열 / 갈라짐 | `hole` | 구멍 / 찢김 |
| `stain` | 얼룩 / 오염 | `deformation` | 변형 / 휘어짐 |
| `discoloration` | 변색 / 색편차 | `other` | 기타 |

## 4. 평가 및 검증 (Evaluation)

### 4.1 검증 원칙
- 학습에 쓰지 않은 **독립 테스트셋**으로 평가.
- 미탐(FN) 샘플은 개별 리뷰(품질 리스크 직결).

### 4.2 평가 지표
| 지표 | 의미 | 비고 |
|------|------|------|
| Recall(재현율) | 실제 결함 중 잡아낸 비율 | **미탐 최소화가 핵심이면 최우선** |
| Precision(정밀도) | 결함이라 판정한 것 중 실제 비율 | 오탐 비용과 연결 |
| F1 / AUROC | 종합 성능 | 임계값 튜닝 참고 |
| 처리 시간 | 장당 추론 시간 | 배치 운영(**D3**)이므로 목표치는 느슨함. Claude 호출 비용과 함께 관리 |
| 오탐/미탐 비용 | 현업 관점 손익 | D5 확정 후 가중 |

> 정량 합격 기준(예: Recall ≥ 0.98)은 **D5 확정 후** 이 표에 수치로 확정한다.
