## 1. 프로젝트 개요

### 1.1 배경 및 목표
- **배경**: 사람 육안 검사에 의존하던 표면 결함 검사를 비전 기술로 자동화·표준화하여 검사 일관성과 처리량을 높인다.
- **검사 대상**: **제조업 기준 PoC**로, VisA의 **PCB 4종(pcb1~4)** 을 1차 대상으로 한다.
  PCB는 정렬된 규칙적 패턴이라 위치별 이상탐지가 잘 맞고, 사내 과제로 확장할 때 성격이 가장 가깝다.
  (VisA의 나머지 8종은 생활 품목이며 필요하면 함께 쓸 수 있다.)
- **데이터 제약**: 회사(사내) 데이터는 활용에 무리가 있어 사용하지 않으며, 오픈 데이터셋과 직접 촬영 이미지만 사용한다.
- **회사 업무 연장 고려**: 이후 사내 과제로 확장할 가능성이 있어, **상업적 이용이 가능한 라이선스**의
  데이터셋만 기본값으로 채택한다 (VisA: CC BY 4.0). 널리 쓰이는 MVTec AD는 비상업(CC BY-NC-SA) 조건이라 제외했다.
- **목표**: 입력 이미지에 대해 (1) 결함 유무 판정, (2) 결함 유형 분류, (3) 결함 위치(영역) 표시를 자동으로 수행한다.
- **성공 기준(초안)**: 아래 [4.2 평가 지표](#42-평가-지표) 참조. 정량 목표는 D5 확정 후 수치화한다.

### 1.2 범위 (Scope)
- **포함**: 데이터 수집/전처리, 결함 정의, 탐지 파이프라인 설계·구현, 평가, 리포팅.
- **제외(확정)**: 실제 생산라인 하드웨어(카메라/PLC) 통합, 대량 실시간 서빙 인프라. 운영 형태는 Streamlit 앱 기반 오프라인/배치로 한다 (**D3**).

### 1.3 용어 정의
| 용어 | 설명 |
|------|------|
| 결함(Defect) | 정상 표면 대비 허용 기준을 벗어난 이상(스크래치, 찍힘, 이물, 얼룩 등) |
| 오탐(False Positive) | 정상을 결함으로 잘못 판정 |
| 미탐(False Negative) | 결함을 정상으로 놓침 (품질 리스크가 가장 큼) |
| ROI | 검사 관심 영역(Region of Interest) |

## 3. 설계 과정 (Design)

### 3.1 접근 방식 후보 비교

| 접근 | 개요 | 장점 | 단점 | 적합 상황 |
|------|------|------|------|-----------|
| A. 고전 CV | 임계값/에지/모폴로지 기반 규칙 | 빠름, 데이터 少, 해석 쉬움 | 조건 변화에 취약 | 결함 패턴이 단순·일정 |
| B. 지도학습 탐지(YOLO 등) | 라벨 이미지로 결함 검출 학습 | 위치+유형 동시 검출, 정확 | 라벨 데이터 필요 | 결함 종류 명확·데이터 확보 |
| C. 이상탐지(anomaly detection) | 정상만 학습, 이탈을 결함으로 | 결함 라벨 거의 불필요 | 유형 분류는 약함 | 결함 샘플 희소 |
| D. Claude 비전 API 직접 판정 | 이미지를 Claude에 전달해 판정/설명 | 라벨 少, 프롬프트로 빠른 시작, 자연어 설명 | 처리량/비용/미세결함 한계 | 소량·애매 케이스·설명 필요 |
| E. 하이브리드(B/C + D) | 전용 모델 1차 스크리닝 + Claude 2차 판정·설명 | 정확도와 설명력 동시 | 구성 복잡 | 실무 균형 (**채택**) |

> **채택: E. 하이브리드** (D2 확정). 구현 순서는 A/C 계열 → D:
> **① 베이스라인**(고전 CV 특징 + 분류기)으로 하한선 → **② 이상탐지**(정상만 학습, 위치 히트맵)
> → **③ Claude 2차 판정**(임계값 근처 애매한 건만). B(지도학습 검출)는 결함 위치 라벨이 충분히
> 쌓인 뒤 검토한다. 실제 구성은 [3.9](#39-3단계-모델-구성).

### 3.2 파이프라인 (초안)

```
[이미지 입력]
    → [전처리: ROI 크롭 / 정규화 / 조명 보정 / 리사이즈]
    → [1차 탐지: 이상탐지 or 전용 검출 모델]  ──(결함 의심 영역)──┐
    → [2차 판정: Claude 비전 API로 유형 분류 + 근거 설명]        │
    → [후처리: 임계값 적용 / 결함 집계 / 합격·불합격 판정]        │
    → [출력: 판정 결과 + 시각화(박스/마스크) + 리포트]  ◀────────┘
```

### 3.3 Claude 연동 설계 (초안)
- **입력**: 원본 또는 크롭된 결함 후보 이미지 + 구조화된 프롬프트(결함 유형 목록, 판정 기준).
- **출력 형식**: JSON 스키마 강제(예: `{"defect": bool, "type": "scratch|dent|...", "severity": 1-5, "reason": "..."}`).
- **역할**:
  - 소량 데이터 단계에서 1차 판정기.
  - 하이브리드 단계에서 전용 모델의 애매한 결과를 재판정하고 **사람이 읽을 수 있는 근거**를 제공.
- **주의**: 미세·저대비 결함은 한계가 있으므로 임계값·해상도 실험 필요. 실시간 처리를 목표로 하지 않으므로(**D3**) 지연시간보다 호출 비용 관리가 관건이다.

### 3.4 구현 아키텍처 — Streamlit 4단계 앱

전체 파이프라인을 **하나의 Streamlit 앱**에서 단계별 페이지로 구현하고, 순차적으로 완성한다.

| 단계 | 페이지 | 주요 기능 | 상태 |
|------|--------|-----------|------|
| 1 | 데이터 수집 (입력) | 오픈 데이터셋 카탈로그, 로컬 폴더 임포트, 이미지 업로드, 합성 샘플 생성, 품질 점검 | ✅ 완료 |
| 2 | 라벨링 | 라벨 검수 큐, 폴더 라벨 검증, 결함 유형 정규화, 마스크 기반 ROI, 층화 분할 | ✅ 완료 |
| 3 | 모델 개발 · 평가 | 베이스라인 · 패치 이상탐지(위치 히트맵) · Claude 2차 판정 · 임계값 조정 · 실험 기록 | ✅ 완료 |
| 4 | 사후 운영관리 (MLOps) | 모델 레지스트리(롤백) · 배치 추론 로그 · 드리프트 감시 · 성능 추이 · 재학습 판단 · 판정 이력 | ✅ 완료 |

**설계 원칙**
- **UI와 코어 로직 분리**: 판정·수집 로직은 `src/vision_ai/`에 두고 Streamlit 페이지는 표시만 담당한다.
  로직을 UI 없이 pytest로 검증할 수 있어야 한다.
- **수집 사실과 사람 판정을 분리**: `manifest.csv`는 "어떤 이미지를 어디서 수집했는지"만 담고,
  사람의 라벨 판정은 별도 이력 파일에 쌓는다 ([3.7](#37-라벨-데이터-계층)). manifest를 직접
  고치지 않으므로 라벨을 되돌리거나 판정 근거를 되짚어 볼 수 있다.
- **원본 파일 불변**: 폴더 임포트는 파일을 이동·복사하지 않고 경로만 인덱싱한다.
- **외부 다운로드 없이도 전 과정 실행 가능**: 오픈 데이터셋은 용량이 크고 약관 동의가 필요하므로,
  VisA와 동일한 구조의 합성 데이터를 **결함 마스크까지 포함해** 생성한다. 덕분에 VisA를 내려받기
  전에도 마스크 기반 ROI 추출까지 그대로 시험할 수 있다. (합성 데이터는 성능 근거로 쓰지 않는다.)

### 3.6 데이터셋 선정 근거 (D7)

| 항목 | VisA (채택) | MVTec AD (제외) |
|------|-------------|-----------------|
| 라이선스 | **CC BY 4.0 — 상업적 이용 가능** | CC BY-NC-SA 4.0 — 비상업 한정 |
| 카테고리 | 12종 (양초·껌·캐슈너트·마카로니·캡슐 등) | 15종 (병·칫솔·목재·가죽·카펫 등) |
| 결함 유형 라벨 | Anomaly 하나로만 구분 (유형 없음) | 결함 유형별 폴더 제공 |
| 결함 마스크 | 제공 | 제공 |
| 규모 | 더 큼, 한 이미지에 여러 개체 | 상대적으로 작음 |

**채택 이유**: 이후 회사 업무로 연장할 가능성이 있어 상업적 이용 가능 여부를 가장 앞에 두었다.
MVTec AD가 결함 유형 라벨까지 준다는 점에서 학습에는 더 편하지만, 비상업 조건이라 확장 시
데이터셋을 갈아치워야 한다.

**대가**: VisA는 결함 유형을 구분하지 않으므로 모든 결함이 `유형 미지정` 상태로 들어온다.
따라서 **결함 유형은 2단계에서 사람이 지정**해야 한다. 이 작업량을 줄이는 것이 2단계 검수 큐의
설계 목표였다.

### 3.7 라벨 데이터 계층

manifest 위에 세 계층을 얹어 유효 라벨을 계산한다 (`labeling.resolve()`).

| 파일 | 성격 | 내용 |
|------|------|------|
| `data/manifest.csv` | 수집 사실 (1단계) | 출처·카테고리·폴더 추론 라벨·품질 지표 |
| `data/labels.csv` | 사람 판정 이력 (append-only) | 누가 언제 무엇을 바꿨는지. **최신 이벤트가 유효 라벨** |
| `data/splits.csv` | 파생 데이터 | image_id → train/val/test. 언제든 재생성 가능 |
| `data/defect_type_map.csv` | 정규화 규칙 | 데이터셋 고유 유형명 → 표준 유형 |

```
유효 라벨 = 폴더 구조 추론 라벨
            → 결함 유형 정규화 매핑 적용
            → 사람 판정 이벤트로 덮어쓰기 (label_source="human")
            → 분할 정보 병합
```

라벨을 덮어쓰지 않고 이벤트로 쌓기 때문에, 나중에 "이 이미지는 왜 결함으로 분류됐나"를
되짚어 볼 수 있다. 4단계 운영관리에서 판정 이력 조회의 토대가 된다.

### 3.8 결함 유형 분류 체계 (확정)

일상 물건 기준으로 정의한다. 오픈 데이터셋의 고유 유형명(예: MVTec AD의 `broken_large`)은
2단계 라벨링에서 아래 표준 유형으로 정규화한다.

| 키 | 설명 | 키 | 설명 |
|----|------|----|------|
| `scratch` | 스크래치 / 긁힘 | `contamination` | 이물 부착 |
| `dent` | 찍힘 / 눌림 | `broken` | 파손 / 깨짐 |
| `crack` | 균열 / 갈라짐 | `hole` | 구멍 / 찢김 |
| `stain` | 얼룩 / 오염 | `deformation` | 변형 / 휘어짐 |
| `discoloration` | 변색 / 색편차 | `other` | 기타 |

### 3.9 3단계 모델 구성

딥러닝 스택(PyTorch 등)을 도입하지 않고 scikit-learn + OpenCV로 구성했다. 설치 부담을 줄이고,
표면 결함이 국소적인 밝기·엣지·텍스처 이상으로 나타난다는 성질을 직접 활용하기 위함이다.

| 구성 | 입력 | 방식 | 산출 |
|------|------|------|------|
| 베이스라인 | 이미지 1장 → 67차원 특징 | 로지스틱 회귀 / 랜덤 포레스트 / 그래디언트 부스팅 | 결함 확률 |
| 이상탐지 | 격자(16px, stride 8) 14차원 특징 | 위치별 정상 분포의 **마할라노비스 거리** | 결함 점수 + 위치 히트맵 |
| Claude 2차 판정 | ROI 크롭 이미지 | `claude-opus-5` 멀티모달 + JSON 스키마 강제 | 결함 유형 · 심각도 · 확신도 · **근거 문장** |

**특징 구성(67차원)**: 밝기 분포(분위수), 선명도(Laplacian), 엣지(Sobel·Canny),
색상(RGB/HSV 평균·표준편차), 고주파 성분(원본−블러), 국소 이상 비율, 구조성(행·열 프로파일 변동),
밝기 히스토그램 16빈, LBP 텍스처 히스토그램 16빈.

**이상탐지가 위치까지 내는 이유**: 격자 칸마다 정상 분포와의 거리를 재므로, 거리 지도 자체가
곧 결함 위치 히트맵이 된다. 별도 위치 예측기가 필요 없다. PCB처럼 정렬된 이미지에서는
`per_position`(위치별 분포)이 유리하고, 이때 정상 이미지가 특징 차원(14)보다 많아야 한다.

**Claude 호출을 아끼는 방식**: 전량을 보내면 비용이 선형으로 늘어난다. 1차 모델 점수가 판정
임계값 **근처**인 이미지만 골라 보내고(`claude_review.select_uncertain`), 결과는
`artifacts/claude_reviews.csv`에 캐시해 같은 이미지를 두 번 청구하지 않는다.
호출 시 `output_config.format`으로 JSON 스키마를 강제하므로 자유 서술을 다시 파싱할 필요가 없다.

**실험 기록**: 학습을 실행하면 설정과 지표가 `artifacts/experiments.csv`에 한 줄씩 쌓이고,
실행별 상세는 `artifacts/runs/<run_id>.json`에 남는다. 4단계 모델 레지스트리의 토대다.

### 3.10 4단계 운영관리 구성

성능 저하는 두 경로로 온다. 조치가 다르므로 나눠서 감시한다.

| 경로 | 감지 방법 | 정답 라벨 | 조치 |
|------|-----------|-----------|------|
| **데이터 드리프트** | 학습 시 입력 분포 대비 PSI | 불필요 | 재학습·전처리 조정 (조명·공정 변경 확인이 먼저) |
| **성능 드리프트** | 사후 검수 정답 vs 모델 판정 | 필요 | 임계값 재조정 또는 모델 교체 |

**모델 레지스트리 (`registry.py`)** — 3단계 실험 기록을 버전으로 승격한다. 승격 시 모델 파일을
**버전 폴더로 복사**하는 것이 핵심이다. 3단계는 같은 경로에 덮어쓰므로, 복사하지 않으면 다음 학습이
과거 버전을 지워 롤백이 불가능해진다. 이전 버전은 `보관` 상태로 남으므로 다시 승격하면 롤백이 된다.

**드리프트 기준선** — 승격 시 학습 분할의 특징별 **분위 경계와 각 구간의 실제 비율**을 함께 저장한다.
비율까지 저장하는 이유는 [5.4](#54-v06-구현-상세-4단계-운영관리)에 적었다.

**추론 로그 (`serving.py` + `monitoring.py`)** — 배치 추론의 입력 요약·점수·판정·처리 시간을 남긴다.
로그가 없으면 성능 저하를 감지할 근거 자체가 없으므로, 운영 감시의 출발점이다.

**성능 측정의 정답 출처** — 2단계에서 **사람이 확인한(`verified`) 라벨만** 정답으로 쓴다.
폴더 구조에서 추론한 라벨을 정답으로 쓰면 자기 채점이 되어 성능 저하를 영원히 못 잡는다.

**재학습 판단** — 신호를 모아 제안을 만들되 **자동 배포는 하지 않는다**. 경보 조건은
(1) 실측 재현율이 등록 시 대비 허용 낙폭 초과, (2) 미탐 발생, (3) 입력 분포 변화.
경고 조건은 (4) 신규 라벨 누적, (5) 로그·정답·기준선 부재, (6) 드리프트 표본 부족.

**판정 이력 조회** — 1~4단계 산출물이 모두 `image_id`로 연결되어 있어, 이미지 하나의
수집 → 라벨 이력 → 모델 판정 → Claude 근거를 한 화면에 모을 수 있다.

## 4. 평가 및 검증 (Evaluation)

### 4.1 검증 원칙
- 학습에 쓰지 않은 **독립 테스트셋**으로 평가.
- 미탐(FN) 샘플은 개별 리뷰(품질 리스크 직결).

### 4.2 평가 지표
| 지표 | 의미 | 비고 |
|------|------|------|
| Recall(재현율) | 실제 결함 중 잡아낸 비율 | **미탐 최소화가 핵심이면 최우선** |
| Precision(정밀도) | 결함이라 판정한 것 중 실제 비율 | 오탐 비용과 연결 |
| F1 / AUROC / AP | 종합 성능 | 결함이 드물면 AP(평균 정밀도)가 AUROC보다 민감 |
| 미탐률 / 오경보율 | FN·FP를 비율로 본 값 | 임계값 조정 화면에서 함께 표시 |
| 최고점 명중률 | 히트맵 최고점이 정답 마스크 안에 있는 비율 | 가장 해석하기 쉬운 위치 지표 |
| Pixel AUROC / IoU@p99 | 픽셀 단위 위치 정확도 | 마스크가 있는 데이터에서만 계산 |
| 처리 시간 | 장당 추론 시간 | 배치 운영(**D3**)이므로 목표치는 느슨함. Claude 호출 비용과 함께 관리 |
| 오탐/미탐 비용 | 현업 관점 손익 | D5 수치 확정 후 가중 |

**임계값 결정 방식 (D5)**: 목표 재현율을 먼저 정하고, 이를 만족하는 임계값 중 **오탐이 가장 적은
값**을 자동 선택한다. 미탐 우선 정책을 코드로 표현한 것이다(`evaluate.threshold_for_target_recall`).
정량 합격 기준(예: Recall ≥ 0.98)은 실제 VisA 데이터로 측정한 뒤 이 표에 수치로 확정한다.

**PSI(Population Stability Index)를 쓰면서 실제로 부딪힌 문제 두 가지**

PSI는 널리 쓰이지만 그대로 쓰면 오경보를 낸다. 두 가지를 측정으로 확인하고 고쳤다.

1. **소표본 과대추정** — 10구간 기준으로 **같은 분포**에서 뽑은 표본인데도 n=40이면 PSI 중앙값이
   0.24("변화" 임계값 0.25에 육박), n=20이면 1.0을 넘었다. 구간당 표본이 적으면 무작위 변동만으로
   PSI가 커지기 때문이다.
   → 표본 수에 맞춰 **구간을 병합**하고(구간당 최소 30개), 60개 미만이면 아예 **판정을 보류**한다.
   보류는 경보가 아니라 경고로 처리해 오경보가 재학습을 유발하지 않게 했다.
2. **동점 값이 많은 특징에서의 오경보** — 분위 경계가 겹치면 남은 구간이 각각 1/구간수를 담지 않는데,
   균등하다고 가정해 계산하고 있었다. 실제로 합성 PCB 데이터에서 `gray_p50`의 평균이
   76.84 → 76.86으로 사실상 그대로인데 PSI가 2.17로 나와 "변화"로 잘못 판정됐다.
   → 기준선에 **구간별 실제 비율**을 저장하고 그것으로 계산하도록 고쳤다.
   같은 데이터에서 변화 특징 8개 → 0개, 평균 PSI 0.123 → 0.011로 정상화됐다.

수정 후 확인한 동작:

| 시나리오 | 결과 |
|----------|------|
| 같은 데이터 재입력 | 안정 (평균 PSI 0.011, 변화 0개) |
| 밝기 +40 (조명 변경) | 변화 (23개 특징, 밝기 계열이 상위) |
| 가우시안 블러 (초점 흐림) | 변화 (55개 특징, 선명도 계열 `lap_p99`이 상위) |
| 정규분포 1σ 이동 | 탐지율 100%, 같은 분포 오경보율 0% |

|------|------|------|
| 승격 시 `TypeError` | `promoted_at`이 전부 결측이면 pandas가 float64로 추론해 문자열 대입을 거부 | 로드 시 문자열 열의 dtype을 object로 고정 |
| 승격과 같은 초에 남긴 라벨이 신규 라벨 집계에서 누락 | 타임스탬프가 초 단위인데 경계를 `>`로 비교 | 경계 포함(`>=`)으로 변경 — 빠뜨리면 재학습이 늦어지므로 한 건 더 세는 쪽이 안전 |
| 3단계 재학습이 등록된 모델을 덮어씀 | 3단계는 고정 경로에 저장 | 승격 시 버전 폴더로 복사. 회귀 테스트로 고정 |

## 6. 다음 단계 (Next Steps)

전체 파이프라인(1~4단계)이 완성되었으므로, 다음은 **합성 데이터를 실제 VisA로 교체해 검증**하는 것이다.
지금까지의 모든 수치는 합성 데이터 기준이라 성능 근거가 되지 못한다.

### 1순위 — 실데이터 검증
1. **VisA 다운로드 후 PCB 4종 등록** — 압축 해제한 루트를 로컬 폴더 임포트(`visa`)로 넣고,
   폴더 구조 해석과 마스크 ROI 추출이 실제 파일(.JPG 확장자·대소문자)에서도 동작하는지 확인한다.
2. **공식 분할 임포트** — `split_csv/`를 적용해 벤치마크와 비교 가능한 분할을 확보한다.
3. **결함 유형 라벨링** — VisA는 유형 라벨이 없으므로 2단계 검수 큐로 표준 10종을 지정한다.
   전량은 부담이므로 PCB 4종 중 1~2종부터 시작한다.
4. **1차 모델 성능 측정** — 베이스라인과 이상탐지를 실제 데이터로 돌려 합성 지표를 대체하고,
   그 결과로 **정량 합격 기준(D5)** 을 4.2 표에 확정한다.
5. **Claude 2차 판정 실제 호출 검증** — API 키 확보 후. 지금은 요청 구성까지만 확인했다(5.3 참조).
6. **운영 감시 실측** — 실데이터로 배치 추론을 돌려 드리프트 기준선을 다시 잡는다.
   합성 데이터 기준선은 실데이터와 분포가 달라 그대로 쓸 수 없다.

### 2순위 — 성능이 부족할 경우의 확장
7. 이상탐지 성능이 한계면 사전학습 CNN 특징으로 패치 특징을 교체한다 —
   `features.patch_features`만 갈아끼우면 되도록 설계했다. 이때 PyTorch 도입을 검토한다.
8. 결함 위치 라벨이 충분히 쌓이면 **지도학습 검출(접근 B)** 을 추가한다.

### 3순위 — 운영 성숙도
9. 드리프트 임계값(PSI 0.1/0.25)과 재학습 기준(신규 라벨 50건, 재현율 낙폭 0.05)은
   업계 통용값과 임의값이다. 실데이터 운영 이력이 쌓이면 이 프로젝트에 맞게 재조정한다.
10. 정기 실행 자동화(스케줄러) — 현재는 화면에서 사람이 배치 추론을 눌러야 한다.
11. 직접 촬영 이미지로 실제 현장 조건 검증 — 오픈 데이터셋은 통제된 환경이라
    조명·각도 변화에 대한 내성은 별도로 확인해야 한다.
