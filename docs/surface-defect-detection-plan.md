## 1. 프로젝트 개요

### 1.1 배경 및 목표
- **배경**: 사람 육안 검사에 의존하던 표면 결함 검사를 비전 기술로 자동화·표준화하여 검사 일관성과 처리량을 높인다.
- **검사 대상 방향**: **일상 생활에서 접할 수 있는 물건의 표면 결함**을 탐지하는 모델을 만든다.
  (예시 후보: 스마트폰/노트북 등 기기 표면 스크래치, 벽·가구 흠집, 과일·채소 표면 흠, 도자기·식기 파손, 의류 얼룩 등 — 구체 품목은 추후 확정)
- **데이터 제약**: 회사(사내) 데이터는 활용에 무리가 있어 사용하지 않으며, 일상에서 촬영 가능한 이미지와 공개 데이터셋만 사용한다.
- **목표**: 입력 이미지에 대해 (1) 결함 유무 판정, (2) 결함 유형 분류, (3) 결함 위치(영역) 표시를 자동으로 수행한다.
- **성공 기준(초안)**: 아래 [4.2 평가 지표](#42-평가-지표) 참조. 정량 목표는 D5 확정 후 수치화한다.

### 1.2 범위 (Scope)
- **포함**: 데이터 수집/전처리, 결함 정의, 탐지 파이프라인 설계·구현, 평가, 리포팅.
- **제외(초안)**: 실제 생산라인 하드웨어(카메라/PLC) 통합, 대량 실시간 서빙 인프라 — D3 확정 후 재정의.

### 1.3 용어 정의
| 용어 | 설명 |
|------|------|
| 결함(Defect) | 정상 표면 대비 허용 기준을 벗어난 이상(스크래치, 찍힘, 이물, 얼룩 등) |
| 오탐(False Positive) | 정상을 결함으로 잘못 판정 |
| 미탐(False Negative) | 결함을 정상으로 놓침 (품질 리스크가 가장 큼) |
| ROI | 검사 관심 영역(Region of Interest) |

## 2. 사전 준비 사항 (Preparation Checklist)

### 2.1 문제 정의
- [ ] 검사 대상 물건/제품 확정 (**D1**)
- [ ] 탐지할 결함 유형 목록 확정 (예: 스크래치 / 찍힘 / 이물 / 얼룩 / 균열 / 색편차)
- [ ] 각 결함의 "합격/불합격" 기준 정의 (크기·개수·위치 임계값) (**D5**)
- [ ] 미탐(FN) vs 오탐(FP) 중 무엇을 더 보수적으로 다룰지 정책 결정

## 3. 설계 과정 (Design)

### 3.1 접근 방식 후보 비교

| 접근 | 개요 | 장점 | 단점 | 적합 상황 |
|------|------|------|------|-----------|
| A. 고전 CV | 임계값/에지/모폴로지 기반 규칙 | 빠름, 데이터 少, 해석 쉬움 | 조건 변화에 취약 | 결함 패턴이 단순·일정 |
| B. 지도학습 탐지(YOLO 등) | 라벨 이미지로 결함 검출 학습 | 위치+유형 동시 검출, 정확 | 라벨 데이터 필요 | 결함 종류 명확·데이터 확보 |
| C. 이상탐지(anomaly detection) | 정상만 학습, 이탈을 결함으로 | 결함 라벨 거의 불필요 | 유형 분류는 약함 | 결함 샘플 희소 |
| D. Claude 비전 API 직접 판정 | 이미지를 Claude에 전달해 판정/설명 | 라벨 少, 프롬프트로 빠른 시작, 자연어 설명 | 처리량/비용/미세결함 한계 | 소량·애매 케이스·설명 필요 |
| E. 하이브리드(B/C + D) | 전용 모델 1차 스크리닝 + Claude 2차 판정·설명 | 정확도와 설명력 동시 | 구성 복잡 | 실무 균형 (**잠정 채택**) |

> **잠정 채택(가정)**: **E. 하이브리드** — 데이터 상황에 따라 초기엔 C(이상탐지) 또는 D(Claude 직접)로 시작하고,
> 데이터가 쌓이면 B(지도학습)를 추가한다. D2 확정 시 확정.

### 3.2 파이프라인 (초안)

```
[이미지 입력]
    → [전처리: ROI 크롭 / 정규화 / 조명 보정 / 리사이즈]
    → [1차 탐지: 이상탐지 or 전용 검출 모델]  ──(결함 의심 영역)──┐
    → [2차 판정: Claude 비전 API로 유형 분류 + 근거 설명]        │
    → [후처리: 임계값 적용 / 결함 집계 / 합격·불합격 판정]        │
    → [출력: 판정 결과 + 시각화(박스/마스크) + 리포트]  ◀────────┘
```

### 3.3 Claude 연동 설계 (초안)
- **입력**: 원본 또는 크롭된 결함 후보 이미지 + 구조화된 프롬프트(결함 유형 목록, 판정 기준).
- **출력 형식**: JSON 스키마 강제(예: `{"defect": bool, "type": "scratch|dent|...", "severity": 1-5, "reason": "..."}`).
- **역할**:
  - 소량 데이터 단계에서 1차 판정기.
  - 하이브리드 단계에서 전용 모델의 애매한 결과를 재판정하고 **사람이 읽을 수 있는 근거**를 제공.
- **주의**: 미세·저대비 결함은 한계가 있으므로 임계값·해상도 실험 필요. 비용/지연시간은 D3에서 관리.

### 3.4 디렉터리 구조 (제안)
```
vision_ai/
├── docs/
│   └── surface-defect-detection-plan.md   # 본 문서

├── src/
│   ├── preprocess/      # 전처리
│   ├── detect/          # 1차 탐지(모델)
│   ├── claude/          # Claude 비전 연동
│   ├── postprocess/     # 판정/집계
│   └── report/          # 리포트/시각화
├── experiments/         # 실험 설정·결과 기록
├── tests/

```

## 4. 평가 및 검증 (Evaluation)

### 4.1 검증 원칙
- 학습에 쓰지 않은 **독립 테스트셋**으로 평가.
- 미탐(FN) 샘플은 개별 리뷰(품질 리스크 직결).

### 4.2 평가 지표
| 지표 | 의미 | 비고 |
|------|------|------|
| Recall(재현율) | 실제 결함 중 잡아낸 비율 | **미탐 최소화가 핵심이면 최우선** |
| Precision(정밀도) | 결함이라 판정한 것 중 실제 비율 | 오탐 비용과 연결 |
| F1 / AUROC | 종합 성능 | 임계값 튜닝 참고 |
| 처리 시간 | 장당 추론 시간 | D3(실시간 여부)에 따라 목표 상이 |
| 오탐/미탐 비용 | 현업 관점 손익 | D5 확정 후 가중 |

> 정량 합격 기준(예: Recall ≥ 0.98)은 **D5 확정 후** 이 표에 수치로 확정한다.
