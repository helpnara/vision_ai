## 이 프로젝트가 보여주려는 것

1. **초보자도** 머신 비전으로 품질 개선을 할 수 있다
2. 모델 **개발뿐 아니라 운영관리(MLOps)까지** 가능하다

아래 항목은 전부 이 두 가지 기준으로 우선순위를 매겼다. 기능이 있느냐가 아니라
**초보자가 스스로 끝까지 갈 수 있느냐**, **운영이 돌아가는 걸 보여줄 수 있느냐**가 기준이다.

## 0. 현재 상태 진단

### 이미 목적에 맞게 되어 있는 것 (다시 손대지 말 것)

- 전문가용 손잡이를 절제했다. 3단계에서 사용자가 정하는 값은 분류기·불균형 보정·평가 분할·
  목표 재현율 넷뿐이고 전부 기본값이 잡혀 있다. 학습률·트리 깊이 같은 건 노출하지 않는다.
- **임계값을 자동으로 고른다.** 초보자가 가장 못 하는 결정을 "목표 재현율을 만족하는 것 중
  오탐 최소"라는 규칙으로 대신 처리한다.
- 다운로드 없이 합성 데이터로 전 과정을 돌릴 수 있다. 진입 장벽이 0이다.
- 4단계 구조가 실제 업무 순서(수집→라벨링→개발→운영)와 같다.

### 목적 대비 가장 큰 공백

**운영관리가 된다는 걸 보여줄 방법이 없다.** 이게 이번 검토에서 새로 나온 가장 중요한 문제다.

4단계의 드리프트 감시·성능 추이·재학습 판단은 **시간이 흐르고 데이터가 쌓여야** 의미가 생긴다.
그런데 지금 시연자가 4단계를 열면 전부 빈 화면이다. 합성 데이터로 배치 추론을 한 번 돌려도
추이가 없어서 "그래프가 하나 찍혔다"로 끝난다. 기능은 다 구현되어 있는데
**작동하는 모습을 보여줄 수가 없다.** 목적이 "운영관리도 가능함을 보여주기"인데 이건 치명적이다.

## A. 운영관리를 시연 가능하게 (최우선 · 이번 검토에서 새로 도출)

- [x] **A1. 운영 시나리오 시뮬레이터** — ✅ 완료 (`src/vision_ai/scenario.py`, 4단계 첫 탭).
      버튼 한 번으로 운영 3개월치를 재생한다.
      기능을 새로 만드는 게 아니라 **이미 만든 4단계 기능이 작동하는 모습을 보이게 하는 것**이다.

      재생 범위: 모델 승격 → 정상 운영(추론 로그 축적) → 조명 변화 주입 → PSI 경고 →
      사후 검수로 성능 변화 확인 → 재학습 신호 발생. **재학습·재승격은 시뮬레이터가 대신하지
      않는다** — 3단계 학습과 레지스트리 승격이라는 실제 기능을 그대로 쓰게 두는 편이
      "운영이 돈다"를 보여주는 데 맞다. 롤백 갈래는 A4로 남긴다.

      드리프트는 밝기/흐림 변환을 `serving.run_batch(transform=...)`에 끼워 주입한다.
      각 구간에서 "지금 무슨 일이 일어났고 왜 이 화면을 봐야 하는지"를 함께 표시한다.

      **측정으로 알게 된 것**: 환경이 변하면 미탐이 늘기 전에 **오탐이 먼저 폭증한다**
      (결함 판정 비율 6% → 34% → 83%). 원인도 정확히 짚힌다 — 조명 변화는 `gray_mean`,
      초점 저하는 `lap_p99`의 PSI가 튄다. 애초에 써 둔 시나리오 설명("재현율이 떨어진다")은
      측정과 달라 바로잡았다. 이 상황의 실제 피해는 결함을 놓치는 것이 아니라
      **사람이 볼 물량이 감당 불가로 늘어나는 것**이다.
- [x] **A2. 승격 안전장치** — 완료 (`glossary.promotion_check()`).
      D5 기준(재현율 0.95 이상, 검수량 절감률 50% 이상) 대비 점검하고, 미달이면 무엇이 왜
      미달인지 보여준 뒤 **확인 체크박스를 켜야 승격 버튼이 열린다.**
      **막지는 않는다** — 기준이 아직 승인 전 제안값이고, 비교·시연 목적으로 일부러 낮은
      모델을 올릴 수도 있다. 지표가 *없는* 것과 *미달인* 것도 구분한다.
- [x] **A3. 드리프트 원인을 평문으로** — 완료 (`glossary.FEATURE_FAMILIES`).
      특징 67개를 전부 현장 언어로 옮겼다(테스트로 누락 방지). PSI 표에 "무엇을 재는가"를
      나란히 붙이고, 변화한 특징에서 **확인할 것**을 추려 보여준다.
      같은 원인을 가리키는 특징이 여러 개 떠도 중복 없이 정리한다.
- [ ] **A4. 롤백을 실제로 보여주기** — 레지스트리에 롤백 기능이 있지만 시연 동선이 없다.

## C. 지표 해석 도움말

앱에 표시되는 지표가 **49종**인데 대부분 숫자만 나온다. 현재 `help=` 도움말은 18개뿐이고
홈 화면에는 하나도 없다. "이 값이 높으면/낮으면 무슨 뜻이고 무엇을 해야 하는지"를 붙인다.

- [x] **C1. 품질 개선 효과를 업무 언어로** — ✅ 완료.
      환산 로직을 `evaluate.business_impact()`로 코어에 모으고 3단계 평가 화면·홈·해석
      스크립트가 **같은 계산**을 쓰게 했다. 화면에서 불량률과 검사 물량을 직접 바꿔볼 수 있다.

      **절감만 보여주지 않는다.** 검수량을 줄이는 대가는 결함을 놓치는 것이므로
      `놓치는 결함` 건수를 항상 나란히 낸다. 둘을 같이 봐야 도입 여부를 판단할 수 있다.
      기대 정밀도가 50% 미만이면 "자동 판정용으로 쓸 수 없다"는 경고를 띄운다.
- [x] **C2. 결과 판정과 다음 행동 제안** — ✅ 완료 (`glossary.verdict()`).
      AUROC와 업무 효과를 보고 "좋음 / 스크리닝용 / 약함"을 판정하고, 재현율 미달·검수량
      절감 없음·현장 정밀도 부족을 각각 짚어 다음에 할 일을 문장으로 낸다.
- [x] **C3. 정밀도 오해 방지** — ✅ 완료. 정밀도 캡션에 "평가 데이터 기준이라 현장과

- [x] **C4. 재현율↔정밀도 맞교환** — ✅ 완료. 임계값 조정 설명을 "한쪽만 좋게 만들 수는
      없습니다 — 어디서 타협할지를 고르는 것"으로 바꿨다.
- [x] **C5. 지표별 설명** — ✅ 완료 (`glossary.METRICS`, 13개 지표).

      PSI 0.10/0.25는 관습값, 재학습 기준은 임의값, 드리프트 최소 표본은 **측정으로 정한 값**
      임을 구분해 화면에 표시한다.

### 도움말 배치 방식 (먼저 결정할 것)

| 방식 | 장점 | 단점 |
|---|---|---|
| `?` 아이콘 (`help=`) | 화면이 깔끔 | 눌러야 보여서 초보자는 그냥 지나침 |
| 지표 옆 캡션 | 바로 보임 | 화면이 길어짐 |
| 상단 접이식 "이 화면 읽는 법" | 절충 | 지표와 설명이 떨어져 있음 |

**혼합안으로 확정** — 핵심 지표(`primary=True`)는 캡션으로 바로 보이게, 부가 설명은 `?`에 둔다.
문구는 `src/vision_ai/glossary.py` 한 곳에 모아 화면끼리 어긋나지 않게 했다.
(전에는 정밀도가 3단계·홈·문서에서 각각 다른 문장으로 설명되고 있었다.)

## F. 기술 작업 (성능·검증)

목적이 "초보자도 할 수 있음을 보여주기"이므로 **성능 개선보다 A~C가 먼저다.**
지금 성능(평균 AUROC 0.830)으로도 "검수량 54% 절감"이라는 이야기는 성립한다.

- [ ] **성능 개선** — E의 결정 후. 공개 벤치마크는 사전학습 특징 기반이 0.95 내외다.
- [ ] **재현율 목표 미달 해소** — 홀드아웃 평균 0.925 (제안 기준 0.95). pcb4가 0.840으로 가장 낮다.
- [ ] **결함 유형 라벨링** — VisA는 유형 라벨이 없다. 2단계 검수 큐로 PCB 1~2종부터.
- [ ] **실데이터 드리프트 기준선 재수립** — 현재 기준선은 합성 데이터라 실데이터에 쓸 수 없다.
      A1(운영 시뮬레이터)과 함께 하면 효율적이다.
- [ ] **지도학습 검출(접근 B)** — 결함 위치 라벨이 쌓인 뒤. 단 공식 1cls 분할은
      train에 결함이 0장이라 그대로 못 쓴다. 별도 분할이 필요하다.
