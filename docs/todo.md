## 1. 다음 작업 — 화면 구성 개선 및 도움말 (우선)

합성 샘플로 1~4단계를 실제로 돌려본 결과, **기능은 되지만 화면이 불편하고 지표 해석에
설명이 없다**는 피드백이 나왔다. 기능 추가보다 이쪽이 먼저다.

### 1.1 화면 구성 (UX)

- [ ] **진행 순서 안내** — 처음 들어온 사람이 1→2→3→4 순서를 알 방법이 없다.
      홈에 "지금 해야 할 다음 단계"를 상태 기반으로 표시하고, 각 페이지 끝에 다음 단계 링크를 둔다.
- [ ] **빈 상태(empty state) 개선** — 데이터가 없을 때 "라벨된 이미지가 없습니다" 같은 오류 문구만
      나온다. 무엇을 해야 하는지와 그 화면으로 가는 링크를 함께 준다.
- [ ] **탭이 많다** — 페이지당 5~6개이고 어느 탭부터 봐야 하는지 표시가 없다.
      기본 진입 탭을 정하거나, 완료된 탭에 표시를 붙이는 방안을 검토한다.
- [ ] **배포본 첫 방문자용 빠른 시작** — 홈에서 합성 데이터 생성 → 분할 → 학습까지
      한 번에 실행하는 버튼. 지금은 1단계 안쪽 탭까지 직접 찾아 들어가야 한다.
- [ ] **배포본 안내 문구** — 컨테이너 재시작 시 데이터·모델·이력이 사라진다는 점을
      README에만 적어 뒀다. 앱 안에서도 보이게 한다.

### 1.2 지표 해석 도움말

앱에 표시되는 지표가 **49종**인데 대부분 숫자만 나온다. "이 값이 높으면/낮으면 무슨 뜻인지,
무엇을 해야 하는지"를 붙인다. 특히 아래는 오해하기 쉬워 우선순위가 높다.

- [ ] **정밀도** — 시험 구성(정상:결함 = 1:1)과 실제 불량률에서 값이 크게 다르다.
      홈에는 이 경고를 넣었지만 3단계 평가 화면에도 같은 설명이 필요하다.
- [ ] **AUROC / AP** — 언제 어느 쪽을 봐야 하는지 (결함이 드물면 AP가 민감).
- [ ] **재현율 / 정밀도 / 미탐 / 오탐** — 맞교환 관계임을 설명. 임계값을 움직이면
      한쪽이 오르고 다른 쪽이 내려간다는 것을 화면에서 보이게 한다.
- [ ] **임계값 자동 선택 정책** — "목표 재현율을 만족하는 것 중 오탐 최소"라는 규칙이
      화면에 설명되어 있지 않다.
- [ ] **PSI(드리프트)** — 0.10 / 0.25 기준의 의미, "표본 부족"이 뜨는 이유(구간당 30건,
      최소 60건), 왜 경고이지 경보가 아닌지.
- [ ] **최고점 명중 / 픽셀 AUROC / IoU@p99** — 명중률이 낮아 보여도 무작위 대비로 봐야 한다는 점
      (VisA PCB 결함은 이미지의 0.57%라 무작위 명중 확률이 0.57%다).
- [ ] **재학습 판단 기준** — 신규 라벨 50건, 재현율 낙폭 0.05는 임의값이다.
      화면에 근거와 함께 표시하고 조정 가능하게 할지 검토한다.
- [ ] **품질 지표** — 선명도(Laplacian 분산) 100, 밝기 40/215 기준의 의미.

### 1.3 방식 제안 (내일 결정)

도움말을 어디에 둘지 먼저 정하는 게 좋다. 후보:
- `st.help` / `?` 아이콘 (`help=` 인자) — 화면이 안 지저분해지지만 눌러야 보인다
- 지표 옆 캡션 — 바로 보이지만 화면이 길어진다
- 페이지 상단 접이식 "이 화면 읽는 법" — 절충안

> 전면 UX 점검을 한 것은 아니고, 실제 사용 중 나온 불편과 코드에서 확인된 것만 적었다.
> 내일 화면을 같이 보면서 항목을 더 채우는 게 좋겠다.

## 2. 대기 중인 결정 (확인 필요)

- [ ] **D5 재현율 목표** — 0.95로 확정할지, 미탐 비용이 크면 0.98 이상으로 올릴지.
      업무 판단이 필요하다. 올리면 오탐이 늘어 검수량 절감 효과가 줄어드는 맞교환이다.
      (근거: [설계 문서 4.4](surface-defect-detection-plan.md))
- [ ] **성능 개선 방향** — 사전학습 CNN 특징 도입 여부. 용량 확인 결과 아래와 같아
      **cv2.dnn + ONNX(추가 용량 0MB)** 를 권한다.

  | 방식 | 추가 용량 | 비고 |
  |---|---|---|
  | PyTorch (PyPI 기본) | 약 1.7GB | 배포본 용량 위험 |
  | PyTorch CPU 전용 | 약 200MB | `download.pytorch.org`가 이 환경에서 차단됨 |
  | onnxruntime | 18MB | |
  | **cv2.dnn (이미 설치됨)** | **0MB** | ONNX 로더 확인 완료 |

  단, ONNX 모델 파일(ResNet18 기준 약 45MB) 확보 경로를 먼저 찾아야 한다.
  이 환경은 `huggingface.co`·`github.com`이 차단되어 있다.
- [ ] **`ANTHROPIC_API_KEY`** — 3단계 Claude 2차 판정을 실제 호출로 검증하려면 필요하다.
      배포본은 Settings → Secrets에 넣으면 코드 수정 없이 동작한다.
